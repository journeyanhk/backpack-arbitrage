# 变更提案: 审计报告安全修复（P0/P1 缺陷修复 + 轻量账本）

## 需求背景

外部《代码安全审计》（2026-08-05 版 bpx_arb_ccxt.py v4.0）指出当前执行器存在数个 P0 级缺陷：
追单/平仓价格方向写反、永续平仓缺少 reduceOnly、合约数量用 abs() 丢失方向、
OrderNotFound 被伪造成交、部分成交漏记/重复记账、现货卖单无条件 autoBorrow、
平仓关闭全账户持仓、费率低于门槛仍开仓、服务监听 0.0.0.0 且 POST 无认证。

底线要求：现阶段只做 DRY-RUN；修复全部 P0 后，用独立子账户和最小仓位测试。

## 变更内容

1. 修正四个 taker/平仓价格方向（可成交的 cross price + 滑点上限）
2. 永续平仓加入 reduceOnly，禁止反向开仓
3. 合约持仓按多空方向识别（signed contracts × contractSize 换算基础资产）
4. OrderNotFound 改为 UNKNOWN 状态，进入对账而非伪造成交
5. 撤单后重新确认最终成交量；部分成交按"已确认增量"记账，杜绝漏记/重复
6. 引入 SQLite 轻量账本（orders / fills / strategy_positions / tasks），重启可恢复
7. 开仓买入才允许 autoBorrow（借 USDC）；平仓卖现货禁止借入标的币，允许赎回出借
8. 平仓仅关闭策略自有持仓（账本归属），不动人工持仓；启动对账发现未知敞口则禁止开仓
9. 费率硬门槛：费率为负或净年化不达标时拒绝开仓；按实际结算周期计算年化
10. leverage 真正参与目标名义计算（target_notional = capital × leverage）
11. 部分成交立即追单（不等待整腿成交），追单失败优先回滚已成交腿，杜绝长时间裸敞口
12. 服务只监听 127.0.0.1；POST 接口增加 X-Auth-Token 认证；实盘缺 key/缺 token 拒绝启动
13. /api/open、/api/close 改为任务模式，后台结果可查询，不丢弃失败信息

## 影响范围

- **模块:** 交易执行引擎（execute_pair / close_pair）、订单辅助（_place_limit / _check_order_filled）、持仓与平仓（open_position / close_position）、状态展示（_build_state）、Flask API、启动逻辑
- **文件:**
  - `bpx_arb_ccxt.py`（主文件，v4.0 → v5.0）
  - `templates/bpx_arb.html`（token 注入 + 任务轮询）
  - `.gitignore`（新增 arb_ledger.db）
  - `README.md`（风险提示与运行说明）
  - `helloagents/`（新建知识库 + 方案包）
- **API:** POST /api/open、/api/close 返回 task_id；新增 GET /api/task/<id>；POST 需 X-Auth-Token（配置时）
- **数据:** 新增 SQLite 账本 `arb_ledger.db`（订单/成交/策略持仓/任务）

## 核心场景

### 需求: 追单与平仓价格方向正确
**模块:** 交易执行引擎

#### 场景: 现货买入追单
现货腿成交、合约腿未成交时，合约卖出追单必须以可成交价格挂单（买一或更低）
- 追单价格 = 合约买一 × (1 - 滑点上限)，而非卖一
- 追单若在滑点上限内无法成交，回滚已成交的现货腿

#### 场景: 永续买入平仓
- 平仓买单价格 = 卖一 × (1 + 滑点上限)，必带 reduceOnly
- reduceOnly 保证即使重复请求也不会翻成多头

### 需求: 订单状态可对账，禁止伪造成交
**模块:** 订单生命周期

#### 场景: 订单查询返回 OrderNotFound
- 状态标记 UNKNOWN，不假定成交、不重发同单
- 短暂重试后仍未知 → 冻结该腿并提示人工处理

#### 场景: 撤单时竞态成交
- 撤单返回后重新确认订单最终成交量，用已确认增量记账
- 新订单只下"剩余未确认量"，杜绝重复对冲

### 需求: 部分成交增量记账
**模块:** 账本

#### 场景: 现货全成、永续部分成交
- 账本按"本次确认累计量 - 上次确认累计量"记录增量
- 新订单成交后仅登记新增量，旧订单已成交量不丢失

### 需求: 平仓只关闭策略持仓
**模块:** 平仓

#### 场景: 账户原有 XRP 人工持仓
- 平仓仅按账本记录的策略持仓量平，不触碰人工持仓
- 启动时对账：发现未知持仓/未知订单 → 禁止新开仓并提示

### 需求: 借贷闭环
**模块:** 借贷

#### 场景: 开仓买入现货
- 允许 autoBorrow 借 USDC；买入的标的币自动出借

#### 场景: 平仓卖出现货
- 允许 autoLendRedeem 赎回出借标的币；禁止 autoBorrow 借入标的币
- 平仓后验证 USDC 债务归零，未归零则报告失败

### 需求: 费率硬门槛
**模块:** 开仓校验

#### 场景: 资金费率为负或净年化低于门槛
- 拒绝开仓，返回明确错误，不再仅警告

### 需求: 服务安全
**模块:** Flask API

#### 场景: 局域网内他人访问
- 默认只监听 127.0.0.1；POST 需 X-Auth-Token（未配置时 DRY-RUN 自动生成并注入页面）

#### 场景: BPX_LIVE=1 但缺 key
- 拒绝启动并输出明确错误

## 风险评估

- **风险:** 行为变更（追单价/平仓量来源/费率门槛）影响现有使用习惯
- **缓解:** 保持 DRY-RUN 默认；所有参数可配置；变更全部写日志；README 同步说明
- **风险:** 账本与真实持仓不一致导致误判
- **缓解:** 启动对账 + 平仓数量取 min(账本量, API 可卖量) 双保险
- **风险:** 追单回滚在市场剧烈波动时滑点
- **缓解:** 回滚仅限滑点上限内；失败则标记 EXPOSED 并高亮提示人工处理
